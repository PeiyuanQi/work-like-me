# Style Profile: Weapons, Props, and Objects

## Corpus basis

- Source category: `05_Weapons-Props-and-Objects`
- Coverage: 132 projects and 132 media files
- Common production evidence: Primarily Photoshop-style concept design, sometimes supported by hard-surface 3D
- Provenance boundary: derived from aggregate metadata and representative visual inspection on 2026-08-02; no source artwork is bundled with this skill.

## Best-fit modes

- isolated hero prop
- weapon or equipment design sheet
- artifact with narrative context
- icon-scale game item

## Visual grammar

- Use one dominant silhouette and a clear grip, interface, opening, or wear pattern.
- Separate structural, functional, and decorative layers.
- Let scratches, residue, polish, repairs, and patina describe use.
- For fantasy objects, tie ornament to fabrication and ownership rather than generic motifs.

## Liked-corpus calibration

- Visual evidence for this category is sparse: one liked project has no eligible image or GIF, so use the broader same-theme local archive as a fallback and do not imitate title cards or promotional thumbnails.
- The fallback pool is heavy on weapons and hard-surface portfolio pieces. Borrow its authored presentation density and material clarity, not its subject silhouette; a tool or appliance should not be distorted into a rifle-like design merely to resemble the fallback.
- Default to an authored prop-concept presentation rather than a uniformly photoreal product render: one hero view plus one controlled functional state or detail inset when the mechanism is not self-explanatory.
- Make the operation path traceable through openings, channels, hinges, transparent windows, exploded spacing, or a partially serviced state.
- Ensure every named material family separates at thumbnail size through value, hue, roughness, edge behavior, or wear response.
- Let function alter the outer contour. Intake, reservoir, grip, guard, hinge, or working head should prevent the result from collapsing into a generic sealed suitcase or beveled game crate.
- The hero view should reveal the primary operation path by itself; use an inset to clarify a hidden step, not to rescue an unreadable closed object or duplicate the same view.

## Generation priorities

1. Lead with the use action and the silhouette change it causes.
2. Name the visible operation path and one serviced or active state before listing materials.
3. Limit the prompt to two or three decisive material families and local wear evidence so construction remains legible.

## Technique workflow

- Define use, user, scale, and manufacturing process first.
- Sketch silhouette families before choosing one design.
- Resolve contact points, balance, assembly, and moving parts.
- Render material breakups under one consistent light direction.
- Reject the first silhouette if its function is understandable only from labels, a cutaway, or a secondary inset.

## Prompt pattern

```text
Production-ready [weapon/prop/object] used by [user] to [use action], outer contour visibly shaped by [grip/intake/reservoir/working head/guard], hero three-quarter view already exposing the primary operation path through [opening/channel/hinge/window], one secondary serviced or active state only where needed, layered [manufacturing logic], two or three strongly differentiated materials with localized wear, authored concept-paint presentation on a quiet ground rather than a glossy product advertisement.
```

## Avoidance pattern

```text
Avoid generic sealed suitcases, evenly beveled game crates, duplicate closed views, an inset doing all explanatory work, uniformly glossy product rendering, unusable grips, ornamental clutter, unsupported blades or barrels, inconsistent scale, random glowing seams, mirrored text, and damage distributed evenly across every surface.
```

## Quality checks

- Function and scale are immediately legible.
- The object could be held, opened, maintained, or manufactured.
- Materials respond differently to light and wear.
- The silhouette remains readable at target size.
- The hero view alone reveals where the user acts, where the mechanism responds, and where output, access, or service occurs when those concepts apply.
- The silhouette would not remain essentially unchanged if its named function were replaced with a different one.
